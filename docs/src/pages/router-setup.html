Router setup: GL-MT3000 with OpenWrt and Podkop

A complete manual path from a new GL-MT3000 (Global or CN) to a router whose Wi-Fi sends everything through our VLESS + Reality server. It works without the chat session: every command is here, and each step says where it runs. Global and CN units follow the same path: we replace GL.iNet's software with official OpenWrt, so the CN restrictions disappear with it.

Before step 1: the unit has passed the arrival check (A1–A8 and B1–B7). Flash only a unit you are keeping. Secrets (VLESS links, Wi-Fi and admin passwords) come from the password manager and never go into files or chat.

Where a step runs: Mac = a terminal on your laptop (prefer your personal laptop: the work Mac is managed and its network settings or GlobalProtect may interfere); browser = the laptop's browser; router = after ssh root@…. Addresses: stock GL firmware 192.168.8.1, recovery mode and fresh OpenWrt 192.168.1.1.

We do not "patch" a CN unit to Global. The known patch writes a country code into the router's Factory partition with dd. That partition also holds the Wi-Fi calibration data: one wrong byte can leave the unit without working Wi-Fi or unbootable. It is unofficial (GL.iNet: "No, this isn't supported") and only matters if you want GL.iNet's own software, which we do not use. Official OpenWrt ignores GL's region setting and uses its own country setting (forum users report CN units work "the same as others"; not confirmed by GL.iNet or OpenWrt).

0. Kit and downloads (Mac, while internet works)

Needed: the router, a USB-C charger of 5 V / 3 A or more, the Ethernet cable from the box, a laptop with an Ethernet port or USB-C Ethernet adapter, internet for the router (a cable from another router, or a Wi-Fi network you know the password of), the VLESS links from the password manager.

The image is also cached in the project at .private/downloads/router-kit/ (checked 2026-11-09). To download it again, on the Mac:

mkdir -p ~/router-kit && cd ~/router-kit
curl -fLO https://downloads.openwrt.org/releases/25.12.6/targets/mediatek/filogic/openwrt-25.12.6-mediatek-filogic-glinet_gl-mt3000-squashfs-sysupgrade.bin
shasum -a 256 openwrt-25.12.6-mediatek-filogic-glinet_gl-mt3000-squashfs-sysupgrade.bin

The printed checksum must be exactly:

c2965b9d49d2ff42bf00c4f04ef73eaae904f553c68af47332fec702b30bf6f4

If it differs, delete the file and download again; never flash a file with a different checksum. There is no separate "factory" image for this model: the sysupgrade image is used for both paths. A newer 25.12.x may exist later: then take its sysupgrade file and its line from the sha256sums file in the same folder.

1. Install OpenWrt

Path A: from the stock GL.iNet page (try first)

  1. Cable. Router powered, laptop plugged into the LAN port (not WAN), laptop Wi-Fi off. On the work Mac, disconnect GlobalProtect from its menu first.
  2. Browser: open http://192.168.8.1 and log in with the admin password set during the arrival check.
  3. Left menu SYSTEM → Upgrade, tab Local Upgrade. Choose the …squashfs-sysupgrade.bin file.
  4. Untick "Keep Settings". GL.iNet settings must not be carried into OpenWrt.
  5. Confirm the install. Do not unplug power for 5 minutes. The LED blinks, then settles.
  6. The router now lives at 192.168.1.1. Unplug and replug the cable so the laptop picks up a new address, then go to step 2.

GL.iNet's documentation describes Local Upgrade for its own firmware files; whether the stock page accepts an official OpenWrt file is not documented (widely done by users; on a CN unit unknown). If it refuses the file, use path B; nothing has changed on the router.

1b. Path B: recovery mode (U-Boot web page)

Use it when path A refuses the file, after a failed flash, or to go back to GL.iNet firmware. It cannot be broken by a bad image: you can always repeat it. Source: GL.iNet "debrick" documentation (dated 2026-10-22).

  1. Power off the router. Laptop cable into the LAN port; nothing in WAN.
  2. Laptop address (Mac): System Settings → Network → the Ethernet adapter → Details → TCP/IP → Configure IPv4: Manually. IP address 192.168.1.2, Subnet mask 255.255.255.0, Router 192.168.1.1. Turn off any VPN or proxy on the laptop (GlobalProtect disconnected).
  3. Hold the reset button firmly with a pin, and while holding it, plug in power. The blue LED flashes 6 times, then turns solid white: release the button. GL.iNet notes that other production batches can show different colours or blink patterns; release when the pattern changes.
  4. Browser: http://192.168.1.1 shows a plain upgrade page. Choose file → the …squashfs-sysupgrade.bin → Update firmware.
  5. Wait about 3 minutes; do not unplug power.
  6. Set the Mac back to Using DHCP (same settings page), replug the cable, go to step 2.

GL.iNet documents this page for its own firmware; that it also accepts the official OpenWrt sysupgrade image is reported by users, not documented (UNVERIFIED). If it is refused, stop and ask (see "When stuck").

2. First login and password

Mac (the cable still in LAN; a fresh OpenWrt has no password yet, so the login asks none). If ssh warns that the host key changed, run the first line, then the second:

ssh-keygen -R 192.168.1.1
ssh root@192.168.1.1

On the router: check what runs, then set the admin password (store it in the password manager first):

cat /etc/openwrt_release
ubus call system board
passwd

Expected: DISTRIB_RELEASE='25.12.6', "board_name": "glinet,gl-mt3000". Then the browser: http://192.168.1.1 opens the OpenWrt web page (LuCI); log in as root with the new password.

If the web page does not open: official release images normally include it. Install it after step 3 gives the router internet: on the router apk update, then apk add luci.

Browser: System → System → General: Timezone Europe/Moscow (or your current one) → Save & Apply.

3. Internet into the router

Option 1: cable (simplest, use it for setup)

A cable from the apartment's router into the WAN port (2.5G). OpenWrt asks for an address automatically. Check on the router:

ping -c 3 1.1.1.1

Option 2: someone else's Wi-Fi (hotel, apartment without cable)

  1. Browser: Network → Wireless. On the radio of the band you want (2.4 GHz reaches further) click Scan.
  2. Next to the network click Join Network. Do not tick "Replace wireless configuration". Name: wwan. Enter its password. Firewall zone: wan. Submit, then Save & Apply.
  3. Check with ping -c 3 1.1.1.1 on the router.

The router's own Wi-Fi then runs on the same channel as that network (one radio does both). A login page (captive portal) in a hotel must be completed from a laptop connected to the router, before Podkop is on, or with the laptop on the hotel Wi-Fi directly. Automatic switching between known networks (travelmate) comes with the setup script later; not needed for the first test.

4. Wi-Fi from the router

Fresh OpenWrt usually starts with Wi-Fi switched off. Browser: Network → Wireless. For each radio (2.4 GHz and 5 GHz) click Edit:

  1. Device Configuration → Advanced Settings → Country Code: the country you are in now (GE Georgia, RU Russia).
  2. Operating frequency: 5 GHz: mode AX, channel 36, width 80 MHz. 2.4 GHz: mode AX, channel 1, 6 or 11, width 20 MHz.
  3. Interface Configuration → General: ESSID WORK (same name on both radios), Network lan. Wireless Security: WPA2-PSK/WPA3-SAE Mixed Mode, a strong key from the password manager.
  4. Save, then Enable the radio, then Save & Apply.

Checks on the router:

iw reg get
iwinfo
Wi-Fi checks (the ones that matter for a CN unit)
#CheckPass
W1iw reg getThe country line shows the code you set (GE or RU), not CN.
W2iwinfoTwo access-point interfaces named WORK, one on channel 36, one on 1, 6 or 11, each with a non-zero Tx-Power.
W3Phone and laptopBoth see WORK, connect, and a phone 2 rooms away still holds the 5 GHz network.

A CN unit that fails W1–W3 after setting the country stays SPARE; note the output and ask. Later the setup script adds the second network DIRECT (no tunnel) and moves the router to its own address range.

5. Podkop: send everything through the server

Requires internet in the router (step 3). On the router, set the clock (certificate checks fail without it), then install Podkop with its official script:

ntpd -q -p 0.openwrt.pool.ntp.org
sh <(wget -O - https://raw.githubusercontent.com/itdoginfo/podkop/refs/heads/main/install.sh)

The script asks in Russian whether to install the Russian translation: n for English, y for Russian. It installs podkop, luci-app-podkop and sing-box (1.13.x from OpenWrt; Podkop needs 1.12.4 or newer).

If GitHub is unreachable from the router, copy the two Podkop files from .private/downloads/router-kit/ (Podkop 0.7.24) to the router with scp -O podkop-0.7.24-r1.apk luci-app-podkop-0.7.24-r1.apk root@192.168.1.1:/tmp/ on the Mac, then on the router apk update and apk add --allow-untrusted /tmp/podkop-0.7.24-r1.apk /tmp/luci-app-podkop-0.7.24-r1.apk. apk update still needs the OpenWrt package server (for sing-box).

Browser: reload, then Services → Podkop. In the main section:

Save & Apply. Then on the router:

/usr/bin/podkop show_version
/usr/bin/podkop global_check

Option names are from Podkop's documentation (podkop.net, 2026-11). Untested here: that a Vision link pastes as-is, and that URLTest with several links works on the standard sing-box (the README mentions an alternative build for "fallback links"). If the link is refused, ask; the fallback is the "Outbound Config" type with a sing-box JSON outbound.

7. Backup and the spare unit

  1. Browser: System → Backup / Flash Firmware → Generate archive. The file contains the VLESS link and Wi-Fi passwords: store it in the password manager as an attachment, not in the project or a chat.
  2. Spare unit: steps 1 and 2 on the spare, then System → Backup / Flash Firmware → Restore backup with that archive. Then install Podkop (step 5, install part only; settings come from the backup) and run step 6. Same model, so the backup restores 1:1. Do this only after the spare's return window has closed, or once you are sure to keep it.

8. Back to GL.iNet stock firmware (if ever needed)

For a return to the seller or to start over. In a browser on the Mac open https://dl.gl-inet.com/router/mt3000/, download the current stable firmware in its U-Boot variant (GL: "Please download the U-Boot compatible firmware"), then follow 1b with that file. Afterwards the stock page is back at 192.168.8.1. A CN unit returns to its CN firmware's behaviour only if you flash CN firmware; for a return to the seller this does not matter for the unit's function.

When stuck

Page does not open

Check the cable is in LAN, Wi-Fi is off, GlobalProtect is disconnected, and the Mac is on DHCP (except during 1b). Replug the cable.

Flash failed, LED odd

Nothing is lost: do 1b. Recovery mode normally lives in a separate part of the flash that an upgrade does not touch.

No internet after Podkop

Services → Podkop → Stop; if internet returns, the link or server is the problem (check V2 from the phone app with the same link).

Need help in a new session

Open the project in Claude Code and say "router setup, step N, here is the output". Paste output, never links or passwords.
